# TapTap 制造 · 输入与积分统计

> 记录你在 [TapTap 制造](https://maker.taptap.cn/) 的**每一次输入**，按**会话**和**项目**统计 token 与积分消耗，侧边栏常驻显示**当前登录用户的各项积分余额**。
> 一个纯本地的浏览器扩展 —— 数据只存在你自己的浏览器里，不上传任何服务器。

## 它是干什么的

平台上的积分数据本身是能看到的，这个扩展只是把散在各个页面的信息**收拢到一处、按维度摆好**，省掉来回翻页和心算：

- 每轮输入的 **tokens / 积分消耗**，直接标在单条消息旁边
- 消耗与**余额差分**对齐，跟你在页面上看到的余额变化是同一个数
- 按**项目 / 会话 / 天 / 小时**归集，想看哪个维度点一下就有
- 侧边栏**常驻**，不用为了看余额反复切页面

一句话：官方给的是原始数据，这里给的是**已经排好版的视图**。

## 功能

**侧边栏（点工具栏图标打开）**

| 模块 | 内容 |
|---|---|
| 正在处理 | **顶部置顶**：只列真的有消息在跑的会话 —— 会话名 · 所属项目 · 已跑时长（秒级跳动）· 本条输入摘要。判定标准是「这一轮还没结束、且近 3 分钟内还有流式输出」，不是最近打开过。没有在跑的任务时整块自动收起 |
| 注入状态 | 顶部显示当前页面是否已生效（未注入会提示刷新） |
| 我的积分 | 当前登录用户的完整积分构成：通用积分（长期 + 到期）、基础积分、付费积分、周期积分、会员卡权益、待发放批次；每 60 秒自动更新 |
| 今日概览 | 今日消耗、输入次数、按小时消耗曲线 |
| 消息归因 | 每条消息旁标注「消耗 X 积分 · 剩余 Y 通用积分」 |
| 完整版入口 | 一键打开完整 Dashboard |

**完整 Dashboard**

- 按日趋势（消耗 / 输入次数）
- 按会话排行 —— 以项目维度对比积分消耗
- 积分余额快照（余额随时间的变化曲线）
- 积分构成明细（最新一份快照的完整拆分）
- 项目积分消耗明细（最近 50 条）
- 输入明细（原文 + tokens + 积分）
- 调试面板（最近 300 条原始捕获事件，用于排障）

**其他**

- **完成通知**：一轮跑完可推送到手机（ntfy / Bark / 自定义 Webhook），见下文
- 1 Token → 积分 的折算倍率可在设置页校准
- 支持导出诊断 JSON（手动触发）
- 全程只读页面数据，**不修改页面任何行为**

## 安装

### 方式一：下载 Release（推荐）

1. 到 [Releases](../../releases) 下载最新的 `taptap-maker-stats-<版本号>.zip` 并解压
2. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
3. 右上角开启 **开发者模式**
4. 点 **加载已解压的扩展程序**，选择解压出来的文件夹

### 方式二：源码加载

```bash
git clone https://github.com/warmA2/taptap-maker-stats.git
```

然后在 `chrome://extensions` 里加载这个目录（`manifest.json` 就在根目录）。

**环境要求**：Chrome / Edge **114+**（Side Panel API），且需 **111+**（`world: "MAIN"` 注入）。

## 使用

1. 打开 <https://maker.taptap.cn/> 正常对话（发消息、等回复）。
   **装好扩展后必须刷新一次页面** —— 注入只在页面加载时发生（侧边栏顶部会显示「已注入页面」）。
2. **点工具栏扩展图标** → 统计面板常驻浏览器右侧边栏，切换标签页也一直存在，每 10 秒自动刷新。
3. 顶部「我的积分」实时显示各项余额；点「我的积分页 ↗」跳官方明细页。
4. 点「完整版 ↗」打开 Dashboard 看趋势、排行、明细。
5. 右键图标 →「选项」可配置**完成通知**（跑完推手机）和积分折算倍率。

> 侧边栏显示「未注入」时：确认扩展已加载 → `chrome://extensions` 点「重新加载」→ **刷新 maker.taptap.cn 页面**。升级扩展后这两步都要做一遍。

## 完成通知（跑完推手机）

长任务跑完不用守在电脑前。右键扩展图标 →「选项」→「完成通知」，选通道、填参数，点 **发送测试通知** 验证能不能收到。

**不需要自己搭服务器，也不需要注册任何账号。** 前两条通道用的都是现成的免费推送服务 —— 手机上装个 App、拿到一串地址填进来就行。

| 通道 | 适合 | 需要填什么 |
|---|---|---|
| **ntfy** | 安卓 / iPhone，免注册免账号 | 一个 topic 字符串。手机装 ntfy → 「订阅 topic」→ 填同一个串 |
| **Bark** | 仅 iPhone，最省事 | App 首页那串 key |
| **自定义 Webhook** | 飞书 / 企业微信机器人 / Server 酱 / 自建转发 | 对应机器人的 Webhook 地址 |

### 用飞书的话，三步

1. 飞书群里点「设置」→「群机器人」→「添加机器人」→「自定义机器人」，随便起个名
2. 复制它给的 Webhook 地址（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx`）
3. 扩展设置页选「**自定义 Webhook**」，地址粘进去 → 保存 → 点「发送测试通知」

如果那个机器人勾了「签名校验」，把密钥也填到「飞书签名密钥」那一栏 —— 扩展会自动算 `timestamp` + `sign`，不用你手算。

> 企业微信机器人同理，地址形如 `qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…`，按域名自动切换消息格式，不需要额外配置。

> 飞书/企微在**发送失败时 HTTP 状态码也是 200**，真错误在响应体的 `code` 里（例如 19001 表示 token 无效）。扩展会读这个字段，所以「发送测试通知」能直接告诉你失败原因，不会给你一个假的成功。


推送内容长这样：

```
TapTap 制造 · 任务完成
示例项目 · 示例会话
耗时 2 分 18 秒 · 消耗 12 积分
「帮我把这一段的内容调整一下…」
```

两个条件开关（都在设置页）：

- **只在 maker 页面不在前台时推送** —— 默认开。人就在电脑前、页面还开着，就不响。
- **任务短于 N 秒不推送** —— 默认 20 秒，免得每句闲聊都弹一次。

补充说明：

- 同一轮只推一次（结束信号和结算回包都会触发，内部按 turnId 去重）。
- 通知里的积分是**延迟 0.9 秒**再读的 —— 等结算数据落地，数字才准。
- 扩展直接把消息发给推送服务本身，**不经过本项目的任何中转**，也不上传你的统计明细和账号信息。用 ntfy 公共频道时，知道 topic 的人能看到消息，所以 topic 起个猜不到的。
- 填了 ntfy.sh / api.day.app 以外的地址（比如自建 ntfy、自建 Bark），保存时会额外申请该域名的访问权限（浏览器弹窗，你同意才生效）。

## 工作原理

扩展以 **MAIN world** 在页面最早期注入（`document_start`），挂钩三个通道。只旁路读取，不改写请求与响应：

| 通道 | 捕获点 | 用途 |
|---|---|---|
| WebSocket 发送 | `_taptap/session/prompt` 请求体（`params.prompt`） | 记录每次输入原文 + 会话 ID |
| WebSocket 接收 | `session/update` 中的 `agent_message_chunk`、`prompt/stopped`、RPC 回包 | 累计输出文本、提取 usage / tokens / credits |
| fetch / XHR | `/api/v1/chats/{id}`、`/api/v1/chats/{id}/context-usage`、`/api/v1/credits`、`/api/v1/credits/batches`、`/api/v1/apps` | 会话标题、上下文用量、积分余额与批次、项目列表 |

**积分数据的优先级**

1. 响应里直接出现的 `credit*` 字段 —— 实测值，最可信
2. 抓不到时按 `(输入 Tokens + 输出 Tokens) × 倍率` 估算，倍率可在设置页校准
3. 余额快照做**差分**校验，两者不一致时以余额变化为准

**校准倍率**：打开官方「我的积分」页，记录一次对话前后的余额差，与 Dashboard 的估算值对比，把倍率改成 `实际扣减 ÷ 估算值` 并保存，Dashboard 会重新估算。

## 数据与隐私

- 所有数据保存在**本机**：IndexedDB 库 `tt-maker-stats`，另用 `chrome.storage.local` 存少量运行状态。
- **默认零外发**：不埋点、不统计、不连任何服务器。唯一的例外是你主动启用的「完成通知」—— 它只把这一条通知内容 POST 到你指定的推送地址，其余统计明细一律不出本机。
- 权限用得很少，且都与功能一一对应：

| 权限 | 用途 |
|---|---|
| `storage` | 存储运行状态与设置 |
| `sidePanel` | 常驻右侧边栏 |
| `scripting` | 向 maker.taptap.cn 注入捕获脚本 |
| `downloads` | 仅在你点「导出诊断」时下载 JSON |
| `host_permissions: https://maker.taptap.cn/*` | 仅在该域名下读取积分与消息 |
| `host_permissions: https://ntfy.sh/*`、`https://api.day.app/*` | 仅在你启用完成通知并选了对应通道时，往这两个推送服务发一条消息 |
| `optional_host_permissions` | 你自己填的 Webhook / 自建服务器域名，保存时才弹窗申请，你拒绝就发不出去 |

**数据表结构**（IndexedDB `tt-maker-stats`，v2）

| 表 | 主键 | 内容 |
|---|---|---|
| `chats` | `id` | 会话 ID → 标题、最后活跃时间 |
| `prompts` | `turnId` | 一轮对话：输入/输出文本、tokens、积分、起止时间 |
| `ctx` | `id` | 会话上下文用量快照 |
| `balances` | `ts` | 积分余额快照 |
| `txns` | `id` | 积分流水（差分校验） |
| `raw` | `seq` | 最近 300 条原始事件（调试用） |

**清除数据**：卸载扩展并清除站点数据即可全部删除。

## 常见问题

**完全没数据？**
扩展加载后要**刷新 maker.taptap.cn 页面**，注入才会发生。改代码后还要在 `chrome://extensions` 点一次「重新加载」。

**Side Panel 打不开 / 图标点了没反应？**
确认浏览器版本 114+。Edge 需在 `edge://settings/sidebar` 允许扩展使用侧边栏。

**积分数字和官方页对不上？**
优先看余额差分（官方口径）。若长期偏差，按上面「校准倍率」调一次。

**某个会话明明在跑，为什么没出现在「正在处理」里？**
判定看的是**这一轮有没有动静**：发出请求后，只要还在收流式片段就算在处理。如果超过 3 分钟没有任何输出，就当作已中断（刷新页面、关标签、断网都会留下这种半截轮次）——它会归到下方「进行中 & 会话耗时」里，标注为未收到结束信号，不再占用顶部位置。

**配了完成通知，手机没收到？**
先点设置页的「发送测试通知」，它会用当前配置真发一条并把错误原因直接显示出来。常见原因：topic / key 填错、任务跑得比「最短时长」还短（默认 20 秒内不推）、maker 页面还开在前台（默认不打扰）、手机端 App 没允许通知权限。发送记录可以在 Dashboard 调试面板里搜 `notify-` 查看。

**平台改版抓不到了？**
打开 Dashboard 底部调试面板，导出诊断 JSON 提 issue —— 里面是原始事件，足够定位解析规则要改哪里。

## 目录结构

```
.
├── manifest.json      # MV3 清单（版本号在这里改）
├── main-hook.js       # MAIN world 注入：钩 WS / fetch / XHR
├── content.js         # 隔离世界桥接：把捕获事件转给 background
├── background.js      # Service Worker：解析、入库（IndexedDB）、聚合查询
├── sidepanel.html     # 侧边栏 UI
├── sidepanel.js
├── dashboard.html     # 完整数据看板
├── dashboard.js
├── options.html       # 设置页（完成通知 / 积分倍率）
├── options.js
└── icons/             # 16 / 32 / 48 / 128
```

**开发**：纯静态、无构建步骤。改完文件 → `chrome://extensions` 点「重新加载」→ 刷新 maker.taptap.cn 页面。版本号只改 `manifest.json` 里的 `version`。
